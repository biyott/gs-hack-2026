# FG-002 화재로 인한 기존 이동 경로 변경

## 1. 목적

화재 영향 구역 또는 통로 제한 변경으로 기존 이동 경로가 대체된 이유를 설명한다.

시뮬레이션 전용 합성 자료다. 실제 현장 사용 지침, 실제 승인·인증·법규 준수의 증거가 아니다. 위험·행동·경로·목적지는 서버 엔진이 결정하며 이 문서는 그 조건에 맞는 설명만 제공한다.

## 2. 적용 조건

fire-gas 실행에서 화재 이벤트 때문에 서버가 기존 경로를 무효화하고 새 안내 버전을 발행한 경우에 적용한다. 이동 설명은 명시적 이동 정책과 새 유효 경로가 모두 있을 때만 사용한다.

검색 적용 시 siteIds, 요청 모드 또는 common, 위험 유형, 역할, 구역·물질·행동·프로필 조건, 유효기간을 모두 확인한다. 합성 문서는 독립 검토 기록과 approved_for_demo 상태가 확인된 데모 검색에서만 사용할 수 있다. draft, retired, 기한 전·만료 문서는 검색 근거에서 제외한다.

## 3. 적용 제외 조건

equipment 실행, 이전 경로만 있는 경우, 실내 대기 정책, 유효 경로가 없는 경우에는 이동 설명을 적용하지 않는다.

## 4. 필요한 입력 필드

- `siteId`
- `simulationType`
- `runId`
- `workerId`
- `actionCode`
- `guidanceId`
- `guidanceVersion`
- `profileVersion`
- `expiresAt`
- `hazardIds`
- `restrictedPathIds`
- `routeVersion`
- `previousRouteVersion`
- `scenarioPolicy`
- `routeStatus`

필수 입력이 없으면 추측으로 채우지 않고 미확인 또는 설정 필요로 남긴다. 이름·생년월일·의료 진단명은 본 검색 절차의 입력이 아니다.

## 5. 행동 코드와 설명

- `GUIDANCE_UPDATED`: 화재로 달라진 최신 안내를 표시하고 이전 경로·음성·설명을 폐기한다.
- `FOLLOW_VALIDATED_ROUTE`: 이동 정책 아래 새 경로가 유효할 때만 최신 경로를 설명한다.

현재 엔진의 actionCode와 일치하는 설명만 사용한다. 본문은 하나의 절차 검색 단위로 유지하여 적용 조건·행동·예외를 함께 확인한다.

## 6. 개인화 적용

새 경로는 현재 profileVersion의 확인된 제약을 반영해야 한다. 문서가 제약을 완화하거나 목적지를 선택하지 않는다.

언어는 preferredLocale을 사용하고 국적으로 추정하지 않는다. 나이·성별에서 이동 능력이나 이해 능력을 추정하지 않으며 미입력 프로필을 제약 없음으로 취급하지 않는다.

## 7. 예외 및 기본 안내

새 경로가 없으면 이동 예시 대신 서버의 경로 없음 기본 안내와 지원 절차를 유지한다. 정책이 실내 대기로 바뀌면 기존 이동 설명을 폐기한다. 생성 중 버전 변경 결과는 전달하지 않는다.

검색 근거 없음·충돌·모델 지연·실패·잘못된 인용·행동 불일치에는 보조 설명을 생략하고 검토된 기본 안내를 유지한다. 실제 경로·목적지·연결 관계·장비 제어·임계값을 생성하지 않는다.

## 8. 한국어 안내 예시

> 화재 상황으로 안내가 {guidanceVersion}으로 갱신되었습니다. 이전 경로를 사용하지 마세요. 이동 정책과 새 유효 경로가 모두 제공된 경우에만 {nextWaypointLabel}을 거쳐 {destinationLabel}로 이동하세요.

## 9. 영어 안내 예시

> The fire situation updated guidance to {guidanceVersion}. Do not use the previous route. Only when both a movement policy and a new valid route are provided, follow it via {nextWaypointLabel} to {destinationLabel}.

## 10. 확인할 상태

- 기존 경로 무효화
- 새 정책·경로·안내 버전
- 이전 음성 취소
- 새 안내 이해 확인

기기 수신 확인, 작업자의 이해 확인, 담당자의 지원 수락, 작업자 또는 엔진의 도착 확인은 각각 별도 상태이며 서로 자동 대체하지 않는다.
