# 시연 현장·크레인 후보·책상 축척 선정안

조사일: 2026-09-21. 대상: 140cm × 50cm 책상, 휴대폰 4대, 크레인 1대를 교체하는 웹콘솔.

## 1. 선정 결과와 확정 범위

- **현장 배경:** 충남 서산 LG화학 대산공장 내 LG-Eni BioRefining HVO/SAF 공장 건설 프로젝트.
- **상세 구현 대상:** 해당 현장을 참고한 자재 인양·장비 접근 시연 구역.
- **시연 구역 규격:** 긴 변 140m × 짧은 변 50m, 7,000m².
- **책상과 시연 구역 축척:** 1:100. 책상 1cm가 모델 공간 1m에 대응한다.
- **장비 선택 목록:** 기존 Spierings SK1265-AT6 포함 6종. 동시에 배치하는 수가 아니라 교체 가능한 프리셋 수다.
- **기본 장비:** 기존 구형 SK1265-AT6, 60m 수평 지브 구성.

**현장의 존재·사업명과 장비 제원은 공개 자료로 확인한 사실이다. 140×50m 상세 구역의 크기·배치·작업 시나리오는 이번에 정한 데모 설계값이다. 실제 HVO 부지 내부의 특정 140×50m 구간을 실측·지리 참조한 결과는 아니다.** 공개 자료에서 신설 HVO 유닛의 정확한 경계와 내부 치수는 확인하지 못했다. 따라서 실제 구간의 측량까지 확정됐다고 기획에 쓰면 안 된다.

### 치수 해석과 모델링 주의점

- **기존 Spierings:** [기존 조사](../cranes/spierings-sk1265-at6-reference.md)와 [모델 설명](../../resources/blender/spierings-sk1265-at6/README.md)을 유지한다. 과거 조사 문서는 당시 추천이라고 기록했지만, 이번 요청의 기존 확정 장비는 저장된 SK1265-AT6 자산으로 식별했다. 현재 eLift의 다른 높이를 섞지 않는다. 16.279m는 접힌 장비의 전체 길이이며 전개 상태 차체 자체의 길이가 아니다.
- **Tadano:** 일본 현행 웹페이지 대신 한국어 GR250N-4 제원판으로 고정한다. 이 PDF의 보조 지브 최대 작업 반경은 **33.9m**다. 최대 지지 폭만으로 네 발의 정확한 좌표를 만들 수는 없으므로 상세 제작 시 평면도와 대조한다. X형 앞뒤 지지 간격은 이번 표에서 확정하지 않았다.
- **LTM:** 385/95 R25 타이어의 높이 3.785m를 사용한다. 동일 도면에는 다른 후방 외곽 구성의 길이 **12.391m**, 타이어별 높이 **3.835m**도 있다. 선택한 외형과 수치가 일치해야 한다. **7.151m는 앞뒤 지지 간격, 6.4m는 최대 좌우 지지 폭**이다. 4.5m는 축소 전개 폭으로 최대 폭과 혼용하지 않는다.
- **Maeda:** 앞 폭 4.808m와 뒤 폭 4.704m는 서로 다른 두 가로 치수다. 둘을 더해 전체 길이로 만들지 않는다. 외곽 패드 기준이며 지지점 중심 좌표와도 구분한다.
- **LR:** 미국판 도면의 21′8″, 16′5″, 20′7″, R15′5″를 환산한 근삿값이다. 각각 하부 전체 길이, 좌우 궤도 외곽 폭, 궤도 길이, 후방 선회 반경에 해당한다. **37′8″≈11.48m는 내려놓은 붐 하부까지 포함한 평면 길이**라서 하부 차체 길이로 쓰지 않는다. 상부 본체 높이는 도면상 약 4.01m이며 옵션은 약 4.45m다. 32m 붐은 14m 기본 구성에 6m·12m 구간을 더한 구성에 대응한다.
- **172 EC-B:** 같은 PDF의 16 HC 175 / UC-0460m 조합을 사용한다. 8쪽 첫 열의 11개 표준 구간 구성에 훅 높이 42.3m가 있다. **4.14m 구간은 이 16 HC 175 구간값이 아니다.** 훅 높이와 타워 철골 전체 높이는 구분한다. 4.6m는 하부 외곽이며 콘크리트 기초 설계 치수를 뜻하지 않는다.

제원 PDF의 인양능력은 반경·붐 구성·지지 상태 등에 따라 달라진다. 이 목록의 외형·크기만으로 실제 작업용 하중 계산이나 출입 제한 거리를 산정하지 않는다. 데모 위험 엔진에는 본체, 지지대, 후방 선회, 인양물과 예정 이동 경로의 형상을 별도 입력한다.

## 4. 책상과 현장 좌표의 대응

| 항목 | 책상 | 모델 공간 | 값의 성격 |
|---|---:|---:|---|
| 긴 변 | 140cm | 140m | 책상은 사용자 제공, 현장은 데모 규격 |
| 짧은 변 | 50cm | 50m | 동일 |
| 면적 | 0.70m² | 7,000m² | 1:100 선형 축척으로 계산 |
| 모눈 1칸 | 10×10cm | 10×10m | 제작 규격 |
| 가장자리 여백 | 각 5cm | 각 5m | 폰 이동을 위한 권장 센터 여유 |
| 내부 이동 범위 | 130×40cm | 130×40m | 가장자리 여백 제외, 폰 외곽은 별도 확인 |
| SK1265 지브 반경 | 60cm | 60m | 제조사 제원 환산 |
| SK1265 지지 간격 | 7.95×7.66cm | 7.95×7.66m | 제조사 받침 중심 간격 환산 |
| LTM 지지 간격 | 7.151×6.4cm | 7.151×6.4m | 제조사 도면 환산 |

폰의 외곽 크기는 축소 장비·작업자의 크기가 아니다. 폰은 위치 입력 장치이며 지도에는 보정한 기준점과 실제 미터 크기의 3D 모델을 그린다. 작은 Maeda를 폰 크기에 맞춰 크게 만들지 않는다.

책상 위에서 긴 변을 +X, 짧은 변을 +Y로 하고 왼쪽 아래를 책상 좌표 (0,0)으로 정한다. 지리적 동서남북과는 아직 연결하지 않는다.

```text
책상 좌표를 cm로 입력하면:
  map_x_m = table_x_cm
  map_y_m = table_y_cm

책상 좌표를 m로 입력하면:
  map_xy_m = 100 × table_xy_m

UWB 상대 좌표를 쓸 수 있을 때:
  map_worker = map_equipment + 100 × R(calibrated_yaw) × uwb_relative_xy_m
```

마지막 식은 UWB에서 유효한 평면 상대 좌표를 얻고 센서 방향·높이·기준점 오프셋을 보정한 경우에만 적용한다. 거리 하나를 임의의 x,y로 바꾸지 않는다. Blender/서버/웹은 실제 크기 **1 unit = 1m**를 유지하고 책상 센서 좌표에만 변환을 적용한다. Blender Z-up과 glTF Y-up 축 변환은 가져오기 경계에서 처리한다.

### 상세 시연 구역의 제작용 배치

아래 좌표와 시설 치수는 모두 **데모 설계값**이다. 실제 HVO 내부 시설 위치·통로·회피 지점을 나타내지 않는다.

| 요소 | 모델 공간 좌표·크기 | 책상 대응 |
|---|---|---|
| 크레인 선회 기준점 | C=(30,25)m | (30,25)cm |
| 기본 지브 방향 | +X, 수평 지브 | 책상 긴 변 방향 |
| 작업 면 | x=15–100, y=12–38m | 85×26cm 영역 |
| 자재 적치 구역 | x=55–75, y=17–29m | 20×12cm |
| 인양 목적지 구역 | x=80–95, y=17–29m | 15×12cm |
| 장애물용 설비 블록 | x=105–120, y=18–30m, 높이 6m | 바닥 15×12cm, 높이 6cm 상당 |
| 우회 통로 중심선 | y=8m와 y=42m, 폭 4m, x=8–132m | 폭 4cm 상당. 실제 폰 외곽 폭과 별개 |
| 회피 후보점 | (125,8), (125,42)m | 해당 cm 좌표 |
| 시작 작업자 위치 | W1=(65,25), W2=(90,40)m | 해당 cm 좌표 |

통로 양 끝과 설비 블록 주위 연결부는 경로 그래프로 제작한다. 회피 후보점의 이용 가능 여부는 현재 위험 형상과 연결성을 검사한 경로 엔진이 판단한다. 테이블 좌표를 정했다는 이유로 모든 상황에서 안전한 목적지로 취급하지 않는다.

### 60m 지브와 책상 폭의 관계

60m 반경의 360° 원은 지름 120m이고, 1:100 책상에서는 **120cm**다. 따라서 폭 50cm 책상 안에 전체 원이 들어오지 않는다. 같은 책상에 이 원까지 넣으려면 이론상 최소 1:240이 필요하고, 여백을 주려면 1:300 등 더 작은 축척을 써야 한다. 그 경우 센서 오차도 더 크게 확대된다.

**확정할 시연 규칙:** 책상은 작업 구역 일부에 대응하고, 크레인 전체 작업 범위는 웹 전체 보기에서 보여준다. 기본 SK1265 자세는 C=(30,25), +X 방향이며, 책상 연동 시연의 선회 각도를 ±15°로 제한한다. 이는 데모에서 선택한 범위이며 장비 자체의 기계적 제한이 아니다. 전체 보기에서는 장비의 원래 크기와 범위를 유지한다.

60m 지브의 끝점은 ±15°에서 x≈87.96m, y≈9.47–40.53m가 된다. 긴 변에 맞춰 배치하면 이 시연 동작은 상세 구역 안에 들어온다. 다른 기종의 크기를 줄여 억지로 맞추지 말고 선택한 붐 길이·각도와 카메라 구도를 바꾼다. 전체 보기에서도 물리적 책상 밖에는 실제 폰 관측이 없음을 구분한다.

## 5. 휴대폰 역할 선택 — 기종 배정 없음

**사용자 확정 사항: 기종별 역할을 고정하지 않는다. Flutter 앱 하나에서 어느 폰이든 실행 시 역할을 선택한다. CCTV에는 보유 기기 중 상대적으로 성능이 낮은 폰을 우선 사용한다.**

| 선택 가능한 역할 | 기종 정책 | 동작 |
|---|---|---|
| EQUIPMENT | 사용자가 어떤 폰에서든 선택 | UWB Controller, 장비 상대 좌표의 원점 |
| WORKER_1 | 사용자가 어떤 폰에서든 선택 | UWB Controlee, 경보 화면·진동·소리 |
| WORKER_2 | 사용자가 어떤 폰에서든 선택 | UWB Controlee, 경보 화면·진동·소리 |
| CCTV | 사용자가 어떤 폰에서든 선택, 낮은 성능 기기 우선 | 후면 카메라, JPEG 5–10fps 전송 |

보유 기기는 S24+ 2대, 사용자 표현 “Galaxy Z Fold8 와이드”, Note20 Ultra다. **Samsung 공식 제원에서 S24+, Z Fold8, Note20 Ultra 5G 모두의 UWB 지원을 확인했다.** Z Fold8은 한국 공식 페이지에 UWB ‘예’로 표기되어 있다. 이 제원 확인과 실제 네 기기의 OS·권한·동시 세션 실기 검증은 구분한다. [S24+ 공식 제원](https://www.samsung.com/es/business/smartphones/galaxy-s/galaxy-s24-plus-sm-s926bzkdeub/), [Z Fold8 한국 공식 제원](https://www.samsung.com/sec/smartphones/galaxy-z-fold8/specs/), [Note20 시리즈 공식 데이터시트, Ultra UWB 주석](https://image-us.samsung.com/SamsungUS/samsungbusiness/pdfs/datasheet/Galaxy-Note20-5G-Series-Datasheet-Sprint.pdf)

역할을 선택한 뒤 필요한 기능을 런타임에 확인한다. UWB 역할은 하드웨어 지원·활성화·권한과 해당 Controller/Controlee 세션 개설을 검사하고, EQUIPMENT는 두 작업자의 동시 수신을 실제로 검증한다. 지원되지 않는 기능은 준비 화면에서 이유를 보여주며 다른 역할 선택을 허용한다. 기종 이름 화이트리스트나 영구 역할 매핑은 두지 않는다. 하드웨어가 없는 폰에서 실제 UWB가 동작한다고 표시하지 않는다. CCTV는 UWB가 필요 없고, 후면 카메라 권한과 목표 프레임 전송을 확인한다.

Android는 Controller 1대와 여러 Controlee의 구조를 지원한다. 그러나 UWB 지원이 곧 방위각 지원이나 정확한 2D 위치 보장을 뜻하지 않는다. Jetpack `RangingPosition`의 거리·방위각·고도각은 사용 불가능할 때 null일 수 있다. 거리만 두 개 얻는 경우 두 작업자는 각각 장비 주위 원 위에 있다는 것까지만 알 수 있다. [Android UWB](https://developer.android.com/develop/connectivity/uwb), [RangingPosition](https://developer.android.com/reference/androidx/core/uwb/RangingPosition)

### 축척 때문에 필요한 좌표 처리

Android 문서는 UWB를 10cm 수준 정확도의 측거리 기술로 설명한다. 이는 이 책상·단말 조합의 보장 오차가 아니다. 축척 영향의 예시로 물리 오차가 5cm/10cm/20cm이면 1:100 지도에서는 각각 **5m/10m/20m**가 된다. 따라서 좁은 통로와 작은 장비의 정밀한 위치를 UWB만으로 약속할 수 없다. [Android 설명](https://developer.android.com/develop/connectivity/uwb)

**구현 권장안:** 이미 사용하는 CCTV에 책상 네 모서리 기준점과 장비·작업자 폰의 식별 표식을 추가한다. 서버가 표식 위치를 평면 좌표로 변환하고, UWB는 실제 상대 거리 관측값으로 함께 보관한다. CCTV를 단순 영상 송신·표시만 하는 기능에서 위치 추적까지 확장하는 제안이다. 위치 정밀도가 필요한 데모를 위한 추가 개발 범위이며 이미 구현된 기능은 아니다.

- `tableDistanceM`(실측)와 `worldDistanceM`(축척 적용)을 분리한다. 화면에도 책상 거리와 가상 현장 거리를 구분한다.
- 장비 폰의 UWB 안테나 위치, 시각 표식 중심, 3D 선회 중심은 서로 다르므로 고정 오프셋을 보정한다. 시각 표식 높이가 책상면과 다르면 높이 차에 의한 투영 오차도 확인한다.
- CCTV만으로 얻은 좌표를 UWB 좌표로 표시하지 않는다. 추적 원천·오차 상태·마지막 관측 시각을 보관한다.
- 장비 폰을 이동하면 UWB 원점도 이동한다. CCTV의 책상 기준 좌표 또는 별도 보정된 장비 위치로 지도에 다시 배치한다. 장비 단독 UWB 원점만으로 세계 좌표의 이동과 회전을 알아내지 못한다.
- 크레인 선회각, 붐 길이, 트롤리 위치는 웹콘솔/시나리오의 별도 입력이다. 장비 폰 한 대의 UWB 측거리만으로 지브 자세를 관측할 수 없다.
- 모든 UWB 역할 앱은 시연 중 화면을 켜고 전경 상태로 유지한다. 동시 두 작업자 거리 수신과 null 각도 처리, 가림·단절 시 상태 처리는 실제 단말로 검증해야 한다.
- CCTV 5–10fps는 프레임 간격 100–200ms이고 총 처리 지연은 별도다. 빠른 움직임의 충돌 회피 성능을 이 수치만으로 주장하지 않는다.

## 6. 기획·RAG와 연결할 데이터

[제공된 RAG 기획](https://emul.site/share/tp3yhmjwfb/p/004-rag-data-fxnyP9s15A)은 공개 공유 페이지의 본문을 확인했다. 위험·경로 엔진이 판단하고 RAG는 근거 검색과 보조 설명을 맡는 구조를 그대로 따른다.

- 상세 지도 ID는 `SITE-CONSTRUCTION-01`을 유지하고 표시 이름에 서산 HVO 참고 현장임을 붙인다. 실제 사업명과 합성 지도의 식별자를 구분한다.
- 폰 역할 `WORKER_1`, `WORKER_2`는 기획의 `WORKER-A`, `WORKER-B`와 명시적으로 매핑한다. 기존 `WORKER-C`는 선택적인 가상 데이터로만 두고 세 번째 실측 작업자로 표시하지 않는다.
- 장비 인스턴스 `EQUIPMENT-A`는 유지하고 모델·제원판·자세 프리셋을 교체한다.
- 카탈로그에는 `equipmentType`, `model`, `specEdition`, `sourceUrl`, `sourcePage`, `lengthM`, `widthM`, `heightM`, `supportGeometry`, `slewOrigin`, `tailSwingRadiusM`, `boomOrJibConfiguration`을 둔다. 미확인 값은 null/미확인으로 보존한다.
- 운송 크기와 작업 외곽, 지지점 중심과 패드 외곽을 서로 다른 필드로 관리한다. 최대 반경을 곧바로 모든 상황의 위험 반경으로 쓰지 않는다.
- 모델 교체 시 이전의 위험 구역·경로·안내 버전을 무효화하고 새 형상으로 다시 계산한다. 바뀐 장비와 옛 경로가 동시에 표시되지 않게 한다.
- 회피 지점은 `REFUGE-01/02`, 통로는 `PATH-A/B/C`처럼 기존 식별자를 활용한다. RAG가 좌표·위험 임계값·안전한 목적지를 새로 만들지 않도록 한다.
- 상세 현장 문서는 `synthetic: true`로 두고 실제 LG·GS 현장의 승인된 안전 지침으로 표현하지 않는다. 중장비 모드와 화재·가스 모드는 기존 기획처럼 분리한다.

## 7. 기획에 복사할 문안

> 본 시연은 충남 서산 LG화학 대산공장 내 HVO/SAF 공장 건설 프로젝트를 배경으로 한다. 공개된 공장 전경으로 주변 지형·시설을 단순화하고, 자재 인양 및 작업자 접근 상황을 재현하는 140m×50m 구역을 상세 제작한다. 상세 배치는 실제 내부 도면을 복제한 것이 아닌 시연용 재구성이다. 140cm×50cm 책상과 모델 공간은 1:100으로 대응한다. 기존 Spierings SK1265-AT6를 기본으로 하여 6종의 크레인 프리셋을 웹콘솔에서 교체한다. 기종별 역할은 고정하지 않으며, 모든 폰에서 실행 시 EQUIPMENT·WORKER_1·WORKER_2·CCTV 중 하나를 선택한다. 시연에서는 네 역할을 한 대씩 사용하고 CCTV에는 상대적으로 성능이 낮은 기기를 우선 배정한다. 정밀한 책상 위치 표시는 영상 표식 추적을 추가하는 방식으로 구현하고 UWB 거리와 함께 표시한다. 위험·경로 판단은 엔진이 수행하며 RAG는 그 결과에 대응하는 데모 지침을 검색해 설명한다.
