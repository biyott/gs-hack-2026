

## 개발 목표

개인별 위험 회피 안내를 검증하는 두 개의 독립적인 시뮬레이션을 구현한다.

| 구분 | 시뮬레이션 1: 중장비 위험 회피 | 시뮬레이션 2: 화재·가스 대응 |
| --- | --- | --- |
| 주요 입력 | 중장비·작업자의 위치, 속도, 이동 방향 | 화재·가스 mock 센서 이벤트, 작업자 위치 |
| 위험 판단 | 장비 예상 이동 영역과 작업자의 위치·경로 비교 | 위험 구역과 작업자의 위치·경로 비교 |
| 안내 내용 | 접근 경보, 회피 경로, 다음 행동 | 대피 경로 또는 상황별 대응 방법 |
| 개인화 | 언어, 이동 제약, 보조 필요 여부 | 언어, 이동 제약, 보조 필요 여부 |
| 검증 목표 | 움직이는 장비를 피하도록 안내하는가 | 위험 유형에 맞는 경로·행동을 전달하는가 |

두 시뮬레이션은 지도·개인 프로필·경로 탐색·알림 기능을 공유하되, 위험 판단 규칙과 시나리오는 분리한다.

- 백엔드: Next.js Route Handlers, TypeScript, Node.js 런타임
- API 데이터 검증: Zod
- 데이터베이스: 로컬 파일 기반 SQLite
- ORM: Drizzle ORM
- SQLite 드라이버: better-sqlite3
- DB 스키마 및 마이그레이션 관리: Drizzle Kit
- 앱: Flutter, Dart

  - MethodChannel: 측정 시작·중지 등 명령 전달

- 앱·웹 → 서버: HTTP API, JSON

- Mock 데이터 생성: TypeScript 기반 서버 시뮬레이션 엔진
- 시나리오 정의: JSON
- 실행 환경: 로컬 PC의 단일 Node.js 서버 프로세스
- 모바일 연결: 같은 네트워크에서 서버 PC의 LAN 주소로 접속

## 시뮬레이션 1: 중장비·작업자 위치 기반 위험 회피

### 목적

중장비와 작업자의 위치 관계 및 이동 상태를 분석해 위험한 접근을 감지하고, 작업자에게 개인별 회피 경로와 행동 지침을 전달한다.

### 입력 데이터

| 대상 | 데이터 | 입력 방식 |
| --- | --- | --- |
| 중장비 | 위치, 속도, 진행 방향, 장비 크기 | 기본 mock, 향후 실제 장비 입력 |
| 작업자 | 위치, 이동 상태 | Mock 또는 실제 UWB |
| 고정 위치 인프라 | 앵커 위치, 지도 좌표 기준 | 설정 데이터와 mock 측위 결과 |
| 공간 | 통로, 장애물, 통제 구역, 회피 지점 | 지도 데이터 |
| 개인 프로필 | 선호 언어, 이동 제약, 보조 필요 여부 | 가상 프로필 |
| CCTV | 주변 상황 | 실제 영상 또는 예시 영상 |

### 처리 흐름

1. 중장비와 작업자의 위치를 수집한다.
2. 위치·속도·진행 방향으로 장비의 예상 이동 영역을 계산한다.
3. 작업자의 현재 위치 또는 이동 경로가 위험 영역과 겹치는지 판단한다.
4. 영향받는 작업자의 이동 제약을 반영해 회피 경로를 탐색한다.
5. 선호 언어로 위험 이유와 다음 행동을 전달한다.
6. 장비 방향이 바뀌면 경로를 재검사한다.
7. 수신 확인과 회피 지점 도착 상태를 관제에 표시한다.

### 주요 시나리오

- 장비가 작업자에게 접근
- 장비의 속도 증가
- 장비의 진행 방향 변경
- 작업자별 이동 제약에 따른 다른 경로 제공
- 유효한 회피 경로 없음
- 장비 또는 작업자의 위치 수신 중단
- 지정 회피 지점 도착 확인

### 구현 범위

- 장비의 이동 영역과 작업자의 노출 판단을 우선 구현한다.
- 장비 회전·작업 장치의 동작은 별도 모델을 구현한 경우에만 반영한다.
- 화재·가스 이벤트는 이 시뮬레이션에 포함하지 않는다.

## 시뮬레이션 2: 화재·가스 기반 위험 회피 및 행동 안내

### 목적

화재·가스 누출 mock 이벤트와 작업자 위치를 이용해 위험에 노출된 사람을 식별하고, 개인별 대피 경로 또는 상황에 맞는 대응 방법을 전달한다.

### 입력 데이터

| 대상 | 데이터 | 입력 방식 |
| --- | --- | --- |
| 화재 센서 | 감지 여부, 발생 구역, 발생 시각 | Mock |
| 가스 센서 | 물질 식별자, 측정값, 단위, 발생 구역 | Mock |
| 작업자 | 위치, 이동 상태 | 기본 mock, 선택적으로 실제 위치 |
| 공간 | 통로, 출구, 집결지, 지정 대피 공간 | 지도 데이터 |
| 대응 정책 | 위험별 행동 코드, 목적지, 적용 조건 | 사전 정의한 시나리오 설정 |
| 개인 프로필 | 선호 언어, 이동 제약, 보조 필요 여부 | 가상 프로필 |
| CCTV | 해당 구역의 상황 | 실제 영상 또는 예시 영상 |

### 처리 흐름

1. 화재 또는 가스 mock 이벤트를 발생시킨다.
2. 시나리오 규칙에 따라 위험 구역과 통행 제한 구간을 지정한다.
3. 위험 구역 안에 있거나 예정 경로가 영향을 받는 작업자를 식별한다.
4. 사전 정의한 대응 정책에서 대피·지정 공간 이동·실내 대기 등 적용 가능한 행동을 선택한다.
5. 이동이 필요한 경우 개인 제약을 반영한 경로를 탐색한다.
6. 선호 언어로 위험 종류와 행동 방법을 전달한다.
7. 위험 구역 변경에 따라 안내를 갱신한다.
8. 이해 확인·도움 요청·집결 상태를 관제에 표시한다.

### 주요 시나리오

- 특정 구역에서 화재 발생
- 특정 구역의 가스 측정값이 데모 경보 조건에 도달
- 기존 대피 경로가 위험 구역에 포함됨
- 화재와 가스 위험이 동시에 발생
- 지정된 정책에 따라 이동 대신 실내 대기 안내
- 유효한 이동 경로 없음
- 센서 데이터 중단 또는 오래된 측정값
- 위험 해제 후 별도 조건에 따른 통행 재개

### 구현 범위

- 화재·가스는 mock 데이터로 구현한다.
- 위험 구역의 확대·축소는 미리 정의한 시간별 영역으로 표현한다.
- 실제 화재·가스 확산을 계산하는 물리 모델은 구현하지 않는다.
- 일반 CCTV 영상만으로 가스 존재 여부를 판단하지 않는다.
- 대응 방법은 사전 검토된 시나리오 정책에서 선택한다.
- 중장비 이동 위험은 이 시뮬레이션에 포함하지 않는다.

## 공통 개인화 기능

| 개인화 항목 | 반영 방법 |
| --- | --- |
| 선호 언어 | 위험·경로·행동 안내의 언어 선택 |
| 계단 이용 여부 | 이용 불가 통로 제외 |
| 이동 속도 범위 | 예상 이동 시간 계산 |
| 이동 보조·동행 필요 | 도움 요청과 지원 상태 표시 |
| 알림 선호 | 글·그림·진동 조합 |
| 프로필 유효성 | 확인 시각과 버전 관리 |

- 국적만으로 언어를 결정하지 않는다.
- 나이·성별만으로 이동 능력이나 행동 제약을 추정하지 않는다.
- 본인이 등록하거나 현장에서 확인한 제약을 우선 사용한다.
- MVP는 한국어·영어의 사전 검토된 문구를 제공한다.
- 수신 확인·이해 확인·지원 수락·도착 확인은 별도로 기록한다.

## 서버 모듈 구성

```
server/
├─ simulation/
│  ├─ engine.ts
│  ├─ equipment-simulator.ts
│  └─ fire-gas-simulator.ts
├─ ingestion/
├─ positioning/
├─ state/
├─ risk/
│  ├─ equipment-risk.ts
│  └─ fire-gas-risk.ts
├─ routing/
├─ guidance/
├─ realtime/
└─ persistence/
```

- `simulation`: 실행·정지·가상 시간·mock 입력 생성
- `ingestion`: 입력 검증과 공통 형식 변환
- `positioning`: UWB 측정값과 지도 좌표 연결
- `state`: 최신 위치·센서·위험 상태 관리
- `risk`: 시뮬레이션별 위험 판단
- `routing`: 통행 제한과 개인 제약을 반영한 경로 탐색
- `guidance`: 대응 정책·행동 코드·언어별 문구 선택
- `realtime`: SSE 연결과 상태 전달
- `persistence`: 설정·프로필·실행 이력·이벤트 저장

## 지도 및 시나리오 구성

```
simulation-data/
├─ maps/
│  ├─ construction-site.json
│  └─ industrial-facility.json
├─ profiles/
│  └─ demo-workers.json
├─ policies/
│  ├─ equipment-response.json
│  └─ fire-gas-response.json
└─ scenarios/
   ├─ equipment/
   │  ├─ approach.json
   │  └─ direction-change.json
   └─ fire-gas/
      ├─ fire-blocked-route.json
      └─ gas-response.json
```

각 시나리오는 다음 정보를 포함한다.

- 시뮬레이션 종류와 시나리오 ID
- 지도 ID와 버전
- 작업자 초기 위치와 프로필
- 시간별 장비 이동 또는 센서 이벤트
- 위험 구역과 대응 정책
- 실행 시간과 난수 seed
- 기대 결과와 검증 항목

## 관제 화면

공통 시작 화면에서 다음 중 하나를 선택한다.

1. 중장비 위험 회피 시뮬레이션
2. 화재·가스 대응 시뮬레이션

각 화면은 공통으로 다음 기능을 제공한다.

- 시나리오 선택
- 실행·일시정지·재개·초기화
- 실행 속도 변경
- 지도·작업자·위험 구역·안내 경로 표시
- 개인 프로필과 안내 언어 변경
- 작업자별 수신·이해·도착 상태 표시
- 도움 요청과 미확인 인원 표시
- CCTV와 이벤트 로그
- 실제 데이터와 mock 데이터 구분

중장비 화면에는 장비 궤적·속도·방향 제어를, 화재·가스 화면에는 발생 구역·가상 측정값·위험 해제 제어를 추가한다.

## 구현 기준

- DB 접근은 서버 측에서만 수행한다.
- 위험 판단과 경로 계산의 기준 상태는 서버가 관리한다.
- 실시간 위치 전달과 DB 이력 저장 주기를 분리한다.
- 좌표 변환·위험 판단·경로 탐색·3D 표시를 분리한다.
- GLB는 시각적 표현에 사용하고 길찾기는 별도 지도 데이터로 처리한다.
- 화면 보간은 표현에만 적용하고 위험 판단에는 사용하지 않는다.
- 오래되거나 끊긴 입력은 정상으로 처리하지 않는다.
- SSE 연결·재연결 시 최신 snapshot을 제공한다.
- 안내 ID·경로 버전·프로필 버전·만료 시각을 관리한다.
- 실행마다 `runId`를 발급하고 초기화 시 이전 실행의 안내를 무효화한다.
- 시뮬레이션 전환 시 기존 타이머·구독·위험 상태를 정리한다.
- 실제 센서 없이 두 시뮬레이션 모두 실행 가능해야 한다.

## 개발 순서

1. 공통 지도·프로필·입력 계약·실시간 통신 구현
2. 중장비·작업자 mock 이동 구현
3. 시뮬레이션 1 완성 및 검증
4. 화재·가스 mock 이벤트와 대응 정책 구현
5. 시뮬레이션 2 완성 및 검증
6. 개인별 언어·이동 제약·예외 처리 통합 검증
7. 실제 UWB 연동과 3D 표현 개선
