위험 구역 확대·CCTV 자동 표시·화면 및 소리 알림·상황 설명·작업자 대응 상태에 ‘AI 최초 조치 공유’를 포함한 통합 안전관리자 관제 기능으로 정리하겠습니다.

## 1. 안전관리자 화면의 목적

안전관리자가 다음 내용을 한 화면에서 파악하도록 한다.

- 어디에서 어떤 위험이 발생했는가
- 어떤 작업자가 영향을 받는가
- AI가 누구에게 어떤 최초 조치를 전달했는가
- 작업자가 안내를 수신하고 이해했는가
- 현재 대응 상황과 추가로 필요한 조치는 무엇인가

중장비 위험과 화재·가스 위험 모두 동일한 관제 구조를 사용한다.

## 2. 통합 관제 화면 구성

| 화면 영역 | 표시 내용 |
| --- | --- |
| 위험 알람 | 위험 종류·구역·등급·발생 시각·미확인 상태 |
| 현장 지도 | 위험 영역, 장비·작업자 위치, 회피·대피 경로 |
| CCTV | 해당 구역의 주 영상과 보조 영상 |
| 상황 설명 | 확인된 사실, 판단 근거, 영향 범위, 미확인 사항 |
| AI 최초 조치 | 대상 작업자, 실제 전달 문구, 경로·목적지, 개인화 조건 |
| 작업자 대응 | 전송·수신·이해·도움 요청·이동·도착 상태 |
| 관리자 조치 | 사건 확인, 담당자 배정, 후속 안내, 지원 요청 처리 |
| 사건 이력 | 최초 발생부터 안내 변경·관리자 개입·종료까지 기록 |

## 3. 위험 발생 시 동작 흐름

### ① 위험 판단과 최초 안내

- 서버가 위험 구역과 영향받는 작업자를 판단한다.
- 개인의 위치·언어·확인된 이동 제약을 반영한다.
- 승인된 대응 정책과 경로 엔진의 결과를 바탕으로 AI 최초 안내를 구성한다.
- 안내 ID·버전·대상·문구·근거를 기록한다.

### ② 작업자와 안전관리자에게 전달

- 작업자 앱에는 화면·음성·진동 안내를 제공한다.
- 안전관리자 화면에는 같은 안내 ID와 버전의 실제 전송 내용을 표시한다.
- 기본 긴급 안내는 관리자 확인이나 RAG 보조 설명 생성을 기다리지 않는다.
- 각 기기의 수신 여부는 별도로 추적한다.

### ③ 관제 화면 강조

- 위험 발생 구역으로 지도를 확대한다.
- 해당 구역의 CCTV 패널을 자동으로 연다.
- 위험 알람과 AI 최초 조치 영역을 강조한다.
- 경고음 후 위험과 최초 조치 현황을 짧게 안내한다.

### ④ 대응 상태 추적

- 작업자의 수신·이해·지원 요청·도착 상태를 갱신한다.
- 미확인 작업자와 도움이 필요한 작업자를 강조한다.
- 위험 변화에 따른 안내 갱신과 관리자 개입을 이력에 남긴다.

## 4. 자동 확대·CCTV·소리 안내

### 위험 구역 확대

- 위험 영역과 영향받는 작업자, 관련 경로가 함께 보이도록 확대한다.
- 건물 내부라면 해당 층으로 전환한다.
- `전체 현장`, `위험 구역`, `선택 사건 고정`, `작업자 따라가기` 기능을 제공한다.
- 위치가 갱신될 때마다 화면을 재이동하지 않는다.
- 다른 사건을 확인 중이면 신규 사건을 별도로 강조하고 우선순위에 따라 전환한다.

### CCTV 표시

- 구역별로 등록된 촬영 범위를 기준으로 관련 카메라를 선택한다.
- 카메라 이름·촬영 구역·연결 상태·영상 갱신 상태를 표시한다.
- 실시간·녹화·mock 영상을 구분한다.
- 영상 지연이나 연결 실패를 정상 영상처럼 표시하지 않는다.
- 영상이 없다는 이유로 센서 경보를 해제하지 않는다.

### 화면·소리 알림

- 위험 종류·등급·구역을 색상과 문구·아이콘으로 함께 강조한다.
- 신규 위험, 위험도 상승, 도움 요청을 우선 알린다.
- 같은 사건의 반복 신호는 묶어 중복 재생을 줄인다.
- 여러 음성을 겹치지 않게 재생한다.
- 소리를 일시 정지해도 화면 경보와 사건 상태는 유지한다.

가상 음성 예시:

> “물류창고 B구역에서 지게차 접근 위험이 감지되었습니다. 작업자 2명에게 회피 안내를 전송했으며, 1명은 수신 확인이 필요합니다.”

## 5. 상황 설명과 AI 최초 조치 표시

상황 설명과 AI 조치는 구분해 표시한다.

| 구분 | 내용 |
| --- | --- |
| 확인된 사실 | 센서 이벤트, 위치, 발생 시각, 통제 구역 |
| 판단 결과 | 위험 유형, 영향받는 작업자, 적용된 정책 |
| AI 최초 조치 | 실제 전송된 행동 지침·경로·목적지 |
| 전달 상태 | 전송 성공 여부, 기기 수신, 이해 확인 |
| 현재 대응 | 이동 상태, 도움 요청, 지원 배정, 도착 |
| 추가 확인 사항 | 통신 단절, 영상 미확인, 미응답 작업자 |
| 근거 | 대응 정책·RAG 문서·버전·갱신 시각 |

가상 화면 예시:

```
사건: 물류창고 B구역 지게차 접근 위험
상태: 대응 중

상황
- 영향 작업자: 2명
- 작업자별 회피 안내 전송
- 수신 확인: 1명 / 미확인: 1명

AI 최초 조치
WORKER-A
- 한국어 안내
- PATH-C를 이용한 지정 회피 지점 이동 안내
- 기기 수신 및 이해 확인

WORKER-B
- 영어 안내
- 계단 이용 불가 조건을 반영한 PATH-D 안내
- 전송됨, 기기 수신 미확인

관리자 확인 사항
- WORKER-B 연결 상태 확인
- 관련 CCTV에서 현장 상황 확인

[전달 문구 보기] [지도에서 보기] [지원 배정] [후속 안내]
```

외국어 안내는 실제 전달 원문과 관리자용 한국어 설명을 함께 제공한다. 개인 프로필은 대응에 필요한 언어·기능 제약만 보여준다.

인원수·센서 값·수신 상태는 서버 데이터로 표시하고, RAG는 관련 지침과 보조 설명을 제공한다. 생성된 설명을 확인된 사실처럼 표시하지 않는다.

## 6. 상태 구분과 관리자 개입

### 반드시 구분할 상태

| 상태 | 의미 |
| --- | --- |
| 안내 생성 | AI 안내 내용을 구성한 상태 |
| 전송 | 서버가 전달을 시도한 상태 |
| 기기 수신 | 작업자 앱이 안내 수신을 확인한 상태 |
| 이해 확인 | 작업자가 이해했다고 응답한 상태 |
| 이동·지원 진행 | 실제 위치 변화 또는 지원 처리 상태 |
| 도착 확인 | 지정 지점 도착을 확인한 상태 |

관리자의 사건 확인·소리 정지·위험 해제·사건 종료도 각각 별도로 관리한다.

### 관리자 조치

- AI 최초 조치와 근거 확인
- 미확인 작업자에 대한 추가 연락
- 지원 담당자 배정과 수락 확인
- 승인된 정책 범위의 후속 안내 전송
- 현장 확인 결과 기록
- 권한에 따른 위험 해제 및 사건 종료

관리자가 변경한 내용은 최초 안내를 덮어쓰지 않고 새 버전으로 기록한다.

```
안내 버전 1: AI 최초 조치
안내 버전 2: 위험 변화에 따른 자동 갱신
안내 버전 3: 안전관리자 후속 조치
```

새 안내가 이전 안내를 대체하면 앱은 기존 경로와 음성을 취소한다. 관리자는 작업자가 새 버전을 실제로 수신했는지 확인할 수 있어야 한다.

## 7. 공통 구현 기준과 완료 조건

- 모든 화면·음성·작업자 안내·조치 기록을 `incidentId`로 연결한다.
- 작업자별 안내는 `guidanceId`와 버전으로 관리한다.
- 관리자 화면 재접속 시 최초 조치 이력과 현재 유효한 안내를 복구한다.
- 동일 센서 신호를 여러 사건으로 중복 생성하지 않도록 한다.
- CCTV 연결 실패·소리 출력 실패·위치 단절을 각각 표시한다.
- RAG 실패 시에도 기본 경보·상황 정보·관리자 조작은 유지한다.
- 여러 관리자가 동시에 접속해도 담당자와 조치 상태가 일치하도록 한다.
- 확인·수정·배정·해제·종료의 수행자와 시각을 기록한다.

완료 기준은 ‘위험 인지 → 구역·영상 확인 → AI 최초 조치 파악 → 작업자 대응 추적 → 관리자 후속 조치’가 하나의 사건 흐름으로 연결되는 것입니다.
