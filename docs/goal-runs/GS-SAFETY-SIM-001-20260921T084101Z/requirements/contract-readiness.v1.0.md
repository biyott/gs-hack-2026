## Motion interpretation without scope change

The selected fixed horizontal SK and tower presets do not need invented telescopic sections, and LR remains the selected 32m assembled boom rather than a telescoping crane. These configuration distinctions do not permit freezing mechanically applicable mobile boom luffing, telescoping and hoisting as unsupported merely because an early asset was rigid. Current controls are implementation status, not the definition of the user's required result. A chosen demo range may be narrower than a manufacturer's total operating envelope if explicitly labeled and implemented consistently; exact source maximums remain separately visible.

All six presets, selected configurations, true metre scale and fixed tower origin remain mandatory. RC-002 tower footprint uncertainty is documented in `clarifications.v1.0.1.md` with Research, Design, Technical and Orchestrator coordination; exact unknown geometry remains null. No original source or goal version is replaced.

## Handoff verification boundaries

Owner self-tests, actual provider probes, build output, device observation and independent QA are different evidence classes. Current source documents and technical declarations can establish what to run and what behavior is intended, but do not establish that the four phones, camera latency, coordinate error, supported crane motion or aggregate user flow passed. The original no-sensor software and actual-device/model obligations remain intact. QA alone issues AC and aggregate verdicts for the identified integrated candidate.
