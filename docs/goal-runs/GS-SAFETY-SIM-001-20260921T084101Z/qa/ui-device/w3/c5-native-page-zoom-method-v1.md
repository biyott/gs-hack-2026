## Smallest GUI commit check, before claiming application zoom

This capability check uses no app or HTTP listener and creates no product evidence:

1. Launch only the granted full Chromium with the fresh persistent profile and no viewport emulation. Record executable/version, launch mode, profile identity, PID/start and actual browser window metadata. Open the exact `chrome://settings/appearance` UI.
2. Inspect the rendered accessibility/DOM structure read-only. Identify exactly one Page zoom control by its actual visible label/association and observed option labels. Record the current option and all visible zoom options. Do not assume a selector, shadow-root structure, option value or native popup availability from another Chrome version. Missing, disabled or inaccessible UI is an explicit unavailable result, not permission to bypass it.
3. Use actual pointer/keyboard input to focus/open that control and choose its displayed 200% option, then commit/close through the normal UI. A keyboard sequence may be derived from the observed option order; retain the actual inputs and selection. Do not assign DOM `value`, dispatch a fabricated change event, invoke `chrome.send`, Settings browser proxies, DevTools zoom/metrics APIs, an extension API, a pref file, CSS, text scale or a direct browser preference setter.
4. Record the selected 200% label/value after commit, move focus away, reload/navigate away and back to the same Settings page, and reread 200% from the recreated control. This is evidence of the Settings UI commit across a WebUI reload. Do not inspect preference storage as a substitute. An uncommitted in-memory select value that reverts remains `UI_COMMIT_NOT_OBSERVED`.
5. Restore the recorded original setting through the same GUI, reread it after reload, close the owned persistent context/browser and record cleanup. Preserve all unavailable/failed steps. A separate restart of the same profile is only needed if cross-browser-restart persistence is claimed; do not claim it from a page reload.

The browser's internal implementation naturally handles the UI action. ## Primary-source basis and review boundary

Read-only external source inspection on 2026-09-22 confirmed the official desktop Help route above and its separate controls for site-specific zoom settings. These establish the proposed user action and need to distinguish defaults from site overrides; they do not establish how the installed executable keys overrides by host/scheme/port.

The current upstream Appearance implementation reads its initial default through `getDefaultZoom()`, derives displayed zoom options from preset factors, and handles the control change by passing the selected factor to `chrome.settingsPrivate.setDefaultZoom(...)`. This supports reloading the Settings UI before rereading its displayed selection. These are browser-internal implementation observations, **not executor instructions to call those APIs**. The source is upstream `main`, not a source identity assertion for installed Chromium1243. [Chromium Appearance source](https://github.com/chromium/chromium/blob/main/chrome/browser/resources/settings/appearance_page/appearance_page.ts)

The pinned historical Appearance source at commit `86bff8b8d1c502460f6b2364489c0015c8d8796a` includes factor `2`, formats factors as percentages, loads the default and handles the control change through that same internal setter. It supports the 200%-factor interpretation, not any current selector or installed-version claim. [Pinned Appearance source](https://chromium.googlesource.com/chromium/src/+/86bff8b8d1c502460f6b2364489c0015c8d8796a/chrome/browser/resources/settings/appearance_page/appearance_page.js)

The current HostZoomMap contract describes a browser-context map with scheme-and-host, host, then default precedence; the host parameter is the URL host portion. This supports the conservative rule that a port change is not a fresh zoom namespace. The supplied legacy ZoomController source likewise tracks profile defaults, page navigation and host-related zoom notifications. Neither establishes current installed propagation timing; the actual app still needs independent measurement. [HostZoomMap contract](https://chromium.googlesource.com/chromium/src/+/master/content/public/browser/host_zoom_map.h), [legacy ZoomController source](https://chromium.googlesource.com/chromium/+/HEAD/chrome/browser/ui/zoom/zoom_controller.cc)
