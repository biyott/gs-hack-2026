## Genuine native browser 200% zoom

V1 lines 118–132 attempt `Control+0`, then five `Control+Equal` chords through Playwright, recording each result. Five chords alone are not proof that Chromium's browser chrome processed them. The run remains `UNRESOLVED_NATIVE_200_PERCENT` unless the actual baseline and final geometry meet its recorded signature. No observation has been performed here.

The signature is relative to a verified 100% baseline: same physical browser/content window; devicePixelRatio changes by 2; layout `innerWidth`/`innerHeight` shrink to approximately one half (integer rounding retained); `visualViewport.scale` remains 1; root/body CSS zoom remain unchanged. Preserve requested viewport, actual outer/inner dimensions, device scale, DPR, visual viewport and CSS zoom at baseline, each chord, final 200%, and reset. The existing 0.03 ratio tolerance belongs to the detector and is not a new product acceptance metric. DPR 2 alone establishes nothing about zoom.

| Mechanism | What it changes / what can be claimed |
| --- | --- |
| Native browser page zoom | Browser's real zoom control, with browser zoom UI displaying 200% where that UI is available, plus correlated layout/DPR evidence and the same unchanged page source. This is the intended UI15 case. |
| `deviceScaleFactor:2` / forced DPR / display scaling | Raster/device-density configuration; it can produce DPR 2 without the native 200% layout reflow. Record separately; not a substitute. |
| CSS `zoom:2`, `transform:scale(2)`, font scaling | Injected or product CSS/text behavior. At most explicitly authorized supplemental stress evidence; not native browser zoom. V1 performs none of these. |
| Pinch / `visualViewport.scale` / CDP page scale | Visual magnification with a distinct visual viewport signal; not native page zoom or equivalent reflow. |
| Halving the requested viewport | Responsive narrow-layout test; it does not prove native zoom even if a screenshot looks similar. |

If headless Chromium ignores the browser accelerator, retain v1's unresolved result. The smallest alternative is a separately granted headed instance using the existing frozen browser and a real browser UI zoom action, with the native 200% indicator and geometry bound to the same tab. A usable headed display/native input mechanism must first be available and authorized; no such capability or successful result is presumed by this note. Do not install a browser extension, add an automation zoom API, manipulate preferences or switch to CSS/DPR to silently close this gap. If actual native UI control remains unavailable, report the native 200% case as unexecuted.

## CJK, bilingual text and clipping

V1 preserves whole target text, text Range rectangles, computed font properties, scroll ancestors and screenshots. Its explicit text enumeration is English `.guidance-primary[lang='en']` and `.worker-action[lang='en']`; Korean may appear incidentally in captures but is not systematically enumerated. Font status and CSS font-family do not alone prove correct fallback glyphs or readable Korean. English primary, manager Korean explanation, original history and current guidance must remain separately identified, especially when a paused current guide expires.

A small derivative should enumerate delivered `.guidance-primary[lang='ko']`, `.guidance-explanation[lang='ko']`, `.worker-action[lang='ko']`, the corresponding English nodes, and the existing Korean labels of tested controls. Keep raw DOM text and authoritative message/version/worker identity where available, individual text Range rectangles, actual font status, container clips and scroll offsets. If line reconstruction is needed, use per-character/word ranges as observations without inserting spans or rewriting text; preserve whitespace and source text separately so normalization cannot hide missing characters. Scroll each required long node/control through its real ancestor to show whether all essential content becomes reachable, with before/after evidence.

Review every resulting capture for missing glyphs, clipped characters, lost destination/action words, overlap, obscured controls and meaningful ambiguity. Inspect native 200% only if it was genuinely achieved; otherwise retain the outstanding zoom case. A short native select may show a truncated collapsed option while the full option remains accessible when opened; record both states and whether native popup pixels were captured. Do not infer permanent loss from a collapsed label alone.

Preserve typography concerns (including orphaned particles or awkward wraps) as such. The earlier bounded candidate-3 wrapping classification in `qa/ui-device/ac15-candidate3-wrapping-classification-v1.md` does not prove C4 web correctness and is not reused as fresh evidence. It explains why an isolated particle line must not become a newly invented mandatory defect when the frozen acceptance's instruction, identifier, readability and action remain intact. Conversely, no wrapping preference excuses actual clipping, missing words, lost meaning or inoperability. No text shrinking, hidden overflow or changed guidance wording is permitted to manufacture a QA pass.
