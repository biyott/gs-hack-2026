## Fixture and correlation contract

- Establish incident A from hazard set A and incident B from a distinct, non-overlapping hazard set B under one run. Record actual incident/hazard IDs and expected impacted workers from independent fixture inputs. A second signal for an existing hazard is not evidence of a new independent incident.
- Include A-only, B-only and shared restricted edges. Record ownership before and after every command. A shared restriction remains while B still owns it; no blanket graph reset is allowed. Use actual frozen graph edges, never invent PATH-D or a new map/floor.
- Pin incident A in administrator context 1. Context 2 may inspect B or all incidents: local selection may differ, but authoritative incident IDs, hazard status, worker responses, assignment, guide versions and audit history must agree after synchronization.
- Use candidate camera-to-zone and floor mapping. The currently published map has GROUND only; test correct GROUND/context and absence of invented floors. If the frozen candidate has additional valid floors, exercise those mappings without creating an additional floor requirement.
- Join snapshots/SSE, DB/audit events, visible current selection, camera identity, guidance envelope/primary lineage, route edge IDs and worker responses by run/incident/worker/version. Capture both admin screens and server state at each step. Screenshots alone cannot prove restriction ownership or persistence.
