The factory passes the existing captured providers to actual `createRagService({db, embedding, llm, timeoutMs:5000})`. It retains default fresh wall/monotonic clocks and candidate cwd initialization. It passes the **same input object and same getCurrent callback** to the actual service and returns the **same service promise**, without constructing a replacement query or result. This is the supported factory seam, not an overridden runtime guidance callback.

All tracked service promises, terminal runtime publications and captured provider operations must settle before the measured phase. The scheduler remains unstarted. Exactly one measured profile command then reissues the selected worker's complete functional profile with a higher version and the four frozen unknown fields. Fields are not removed by QA. Source inspection predicts stripping by the contract parser, but the actual parsed boundary and runtime observations are retained for review.

The normal query is constructed by actual `attachRag`: primary message, hazard type and action, with its actual profile/hazard/context fields and limit3. Actual retrieval passes `query: <that actual query>` into the captured E5 provider. The driver only derives this string afterward as an oracle against the captured service input; it never supplies that derived string to the product.

## Evidence joins and limitations

Warmup and measured captures are separate. Evidence retains the raw injection, actual parsed boundary, immediate/before/final snapshots, ordered in-process bus snapshots, actual service inputs/results, full provider input/output events and returned vectors, provider identities, and database rows.

The exact E5 join requires one measured service invocation for the target's new profile and same run; one corresponding embedding start/completion; the exact attach-built query text; one real unit384-vector; one **new** retrieval row absent from the pre-command database; exact vector and embedding-identity equality; and the service's returned generation ID whose stored guidance ID and time interval bind that retrieval. Multiple overlapping calls, additional new retrieval rows, missing outputs or mismatches withhold the exact join. Capture ranges and vector similarity alone are insufficient.

The existing `captureProviders` helper forwards original texts/input and AbortSignal to actual provider methods, exposes their identity, returns successful provider values unchanged, and rethrows original provider errors. Its recording does create another promise at the provider boundary and performs cloning/hashing. Serialization failures can change observed failure behavior, capture work adds latency, and recorded elapsed time is not a clean product-deadline benchmark. The call index is only a local ledger key. Errors can include sensitive text; retain complete captures privately.

Its `settle()` snapshots currently tracked promises. This driver first drains tracked actual initialization/enrichment promises and waits for terminal publication, then calls `settle()` and repeats if service-call count changed. Historical accepted `guidance.supplement` events count as terminal after a later profile replaces the guide. Failed or incomplete drains produce NOT_RUN; a timeout is not cancellation or proof that native inference stopped. The bootstrap retains database/provider ownership and must not close them while underlying operations remain active. The driver disposes only its isolated runtime and subscription.

`raw-injection.json` deliberately contains all canaries as positive injection evidence. Exclude that explicitly classified QA request artifact and frozen fixture/harness source from product-leak scans; do not blanket-exclude runtime captures, parsed boundary, provider requests/outputs, logs or client envelopes. A scanner should separately assert the raw injection really contained the exact frozen values so absence checks cannot pass without an injection.

Results are only CAPTURED_FOR_REVIEW or NOT_RUN, with no full Q26 PASS. This phase can establish actual E5 inputs on the instrumented component path after genuine contract parsing and engine publication. It does **not** establish what the production Next process's separate E5 instance received. Keep component E5 evidence separate from production HTTP/SSE client envelopes, raw generation proxy captures and application stdout/stderr/log scans. Their complete declared surface coverage and independent review remain required for the frozen case. Physical audio belongs separately to case31/UI, not Q26.
