## Common fixtures and controls

`fixtures-v1.json` preserves G0 seed, clock, sites, A/B/C profile conditions, negative envelope classes, and independent response states. It is deliberately independent from a product schema. An adapter must preserve every field's meaning; inability to represent a field is a contract gap, not permission to remove it. The unknown locale fixture requires the documented explicit fallback plus unknown requested locale; a resolved `ko`/`en` field alone does not prove a confirmed preference.

For every scenario, make three fresh QA-owned SQLite files, migrate and seed using the documented commands, then run the same fixed seed and virtual event times. Use a separate reserved port and QA accounts. Never use or reset the developer DB. Do not run mutable candidate code as final QA. Verify candidate manifest before and after each slice, or use its stable copy. Preserve command output, HTTP/SSE frames, database query results, and normalized traces. Keep original failures and all retests.

Deterministic traces include virtual event time, hazard identity/type/polygon/affected workers, action code, route status/version, destination and ordered waypoint/node IDs. Ignore only fresh run/session IDs and wall-clock timestamps as G0 permits; preserve an explicit mapping where those identifiers appear in joined records. Do not discard differing hazard, event, guidance, profile, or route content as noise.

Route checks use the candidate's frozen map input and an independent graph/segment oracle. Check every segment, not just waypoints: connected graph edges, closed-edge exclusion, worker permissions, hazard intersection, destination existence, safe egress from an initially hazardous origin, and a safe reachable candidate refuge. An independent route validator must not import the production planner or geometry predicates. Tie-breaking is compared across repeats and with documented scenario expectations; QA will not infer expected output from the first product result.

## Execution handoff and limits

Required before binding the executable adapter: canonical API/session contract; documented isolated SQLite path environment variable; migration/seed commands; scenario/map/policy files and expected timeline; deterministic clock/advance interface; state/SSE endpoints and cursor behavior; role/permission matrix; persistence/audit schema; G3 manifest and immutable candidate location. API-level checks will use HTTP and database observations, while pure input geometry can use read-only imports. Production tests are supporting evidence, not the independent oracle.

Each result uses the G0 evidence metadata: goal/run/task/card, protocol/source versions, candidate hash, UTC start/end, executor, environment, commands, input, expected, observed, artifacts and PASS/FAIL/BLOCKED/NOT_RUN. Record immutable first evidence before any retest. Maximum two product reworks per defect and one retry for an identical environment failure. Report defects to QA Lead; do not edit product code.
