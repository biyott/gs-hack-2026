## Required meaning

The original goal, lines43–46, separates screen display, voice execution, device receipt and user response; replacement cancels old speech/queues and obsolete completion callbacks cannot change current state. Lines52–56 separate sound stopping from visible alerts, incident acknowledgement, hazard clearance, passage reopening and incident closure; incident/guide/actor/time must join the current state and first history. AC09–11 require actual device replacement/recovery behavior and coherent incident history. These requirements do not require inventing a device observation the server never received.

Retain three distinct facts:

| Fact | What can substantiate it | What it does not prove |
| --- | --- | --- |
| Historical voice start | Authenticated accepted `voice-started`, its immutable receipt and `worker.voice-started` audit event for the exact primary lineage | Current playback after pause, expiry, disconnect, replacement or restart; completed speech; user understanding |
| Current coordinator/playback state | Current local coordinator state and its attempt/generation; a supported server representation with source/freshness/known run policy | Physical output merely from a callback; device-confirmed cancellation merely from a server pause command |
| Historical terminal outcome | Actual valid completion/failure/unsupported/cancellation evidence where the final contract supports reporting it, with actor/lineage/time | A different primary's terminal outcome, or an invented completion to clear a stale label |

An immutable old `voiceStatus: playing` value may be retained as a labelled last report. It must not be displayed without qualification as **currently playing** after known pause/cancellation/expiry makes that assertion unsupported. A truthful representation may show local cancellation, server-side playback eligibility/cancellation policy, or stale/unknown current device state beside the last received start. Tech/Backend/Mobile/Frontend own the final representation and any contract revision; QA does not prescribe a new `voice-cancelled` enum. If the server has not received a device cancellation confirmation, its state must not claim that such a receipt exists.

Do not erase first guidance, the original start event, receipt/display times, or incident state to obtain a cleaner current voice label. `spokenAt` must not be populated merely because playback was stopped, a duration elapsed, the run paused, guidance expired, or no completion arrived. Receipt, display, understanding, help, support and arrival remain independent. Sound cancellation keeps the appropriate visual alert/incident available; invalid route/guide state is labelled according to its actual validity.
