## Measurement workload and thresholds

The following are agreed demo test targets, not hardware specifications or real safety certification. Required actual-demo run: one server, two connected browser admins, four physical Android roles, equipment and two workers uploading/observed at 10Hz per tracked entity where the source supports it, 30s warmup then 180s measured interval for each mode. Record actual source rate independently; deliberately exercise a 10Hz synthetic position input stream for high-frequency UI isolation even if the physical source differs. Test both modes at 1× scenario speed with ten route/hazard changes distributed across each measured interval. Report server CPU/memory, browser/device/OS, viewport, build type, Wi-Fi/LAN conditions, phone thermal state, app foreground state, and RAG provider timing.

| Camera receive/render rate | Received camera stream 5–10fps in normal steady capture; report render rate separately | Timestamp and monotonic sequence every captured/received/rendered frame; report total frames, duration, 1s buckets, dropped/duplicate frames. Deliberate outage/occlusion segments are separately labelled and excluded only from normal-rate summary. |
| CCTV full latency | p95 capture-to-render ≤1000ms | Capture, upload receive and browser render timestamp linked by frame ID. Measure clock offsets first; preserve raw offsets and uncertainty. ## Fault and safety fixtures

Use deterministic engine events for approach, speed increase, heading change, blocked path, all paths blocked, unknown position and arrival; fire, DEMO-GAS-X, compound risk, expanded region, blocked path, no valid route, sensor disconnected/stale, hazard release and distinct authorized reopening. Compare server route edges against hazard polygons, graph connectivity and per-worker edge permissions; a displayed line alone is not proof. Assert no automatic fabricated route or universal stay-put fallback. Changing equipment model invalidates prior shape, route and guidance first.

Guidance: wrong worker/run/map, duplicated event, reverse version order, expired message, delayed old audio callback, old snapshot after reconnect, pause/reset/role/logout/unmount/foreground return, simultaneous hazards. Assert one app-wide guidance SSE subscription and cleanup with observed subscription count/timers/audio events. TTS error and unavailable language/vibration require screen plus supported modality and explicit failure/fallback state.

RAG: all 18 required documents and schema/body/bilingual review; seeded time boundaries, wrong site/mode/material, common scope, draft/retired/not-yet-effective/expired, synthetic approved versus approved_for_demo, conflict, no match, prompt-like document instruction, wrong citation/chunk, action inversion, invented ID/number/unit/placeholder, provider delay/failure and route/profile changed during generation. Verify FTS5 and vectors independently, fusion and post-filtering; require actual embedding vectors and models for real-search evidence. Keep negative fixtures physically/logically outside normal index.

Security: low-privilege/unauthenticated clear/reopen/close requests, two-admin concurrent assignments, shared versions, actor/time audit records. Search sanitized client bundle, HTTP/model envelopes and logs for seeded canary secrets and unnecessary profile fields; do not write real secrets into fixtures or evidence. Direct browser DB access must not exist.
