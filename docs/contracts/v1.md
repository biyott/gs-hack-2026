## Runtime and ownership

One Node.js22 application process runs Next.js App Router pages and Node Route Handlers at port3000, bound to `0.0.0.0`. SQLite is opened only by server modules through better-sqlite3 and Drizzle. Flutter and browsers use HTTP JSON uploads/mutations and SSE server state. Configurable model providers are inference dependencies, never a second application server or client-visible database.

## HTTP and concurrency

Success responses are direct JSON values, without a `data` wrapper. Failures use `{error:{code,message,currentVersion?}}`. All API handlers use the Node runtime. Authenticated browser sessions use the server-issued cookie; authenticated mobile calls use the server-issued bearer token. Tokens never appear in SSE query strings. Roles are `admin`, `operator`, `support`, `worker`, `device`, `observer`; privilege is resolved by the server, not accepted merely because a request names a role.

| Method/path | Request / response |
| --- | --- |
| POST `/api/session` | `SessionRequest` / `Session`; credential validation and role derivation on server |
| GET `/api/session` | Current authenticated session |
| GET `/api/catalog` | Versioned maps/scenarios/equipment/policy catalog |
| GET `/api/simulation?mode=equipment` | `SimulationSnapshot` (also `fire-gas`) |
| POST `/api/simulation` | `SimulationCommand` / updated `SimulationSnapshot` |
| GET `/api/events?mode=equipment` | SSE event `snapshot`; JSON `SimulationSnapshot` |
| POST `/api/incidents/{id}/actions` | `IncidentAction` / updated snapshot |
| POST `/api/workers/{id}/response` | `WorkerResponse` / updated snapshot |
| POST `/api/tracking/frame` | `FrameUpload` (JPEG base64 in JSON) |
| POST `/api/tracking/uwb` | `UwbUpload`; nullable actual range/angles |
| POST `/api/tracking/calibration` | `Calibration`; reviewed coordinate calibration |

Mutation `requestId` is an idempotency key. `expectedVersion` performs an atomic optimistic-concurrency check against the mode run version; incident mutations also supply `expectedIncidentVersion`. A stale revision yields HTTP409 and must not partially apply. The client fetches/reconciles a fresh snapshot before offering a new action. `runId` changes on reset; old responses, RAG callbacks and guidance are invalidated.

Every SSE connect immediately returns the latest snapshot. History remains available for the incident UI, but reconnection does not replay all old speech. One app-wide subscription is owned by a lifecycle service, closed on logout/role switch/reset/disposal. A mode owns its own run, virtual clock, risk state and timer. `run.virtualTimeMs` drives scenarios; ISO UTC wall-clock `generatedAt`/`expiresAt` controls client message validity. Simulation pause does not silently extend an already issued message expiry.

## Guidance union and compatibility

`guidance.ts` preserves all source003/005 fields plus incident linkage from006. `simulationMode` is `equipment|fire-gas`; guidance `mode` remains `template|rag-assisted`, avoiding a collision between two different meanings of mode.

`messageKey` and `primaryMessageKey` are required compatibility aliases for the same reviewed primary template and must be equal. `primaryMessage` stores actual delivered localized text; `managerExplanationKo` stores the Korean explanation. `requestedLocale`, effective `locale`, and `fallbackLocaleUsed` distinguish requested versus supported language. `profileSnapshot` and `profileVersion` preserve the actual conditions used at transmission, not a reconstruction from the latest profile. `templateCatalogVersion` identifies reviewed template content.

`hazardIds` is the related hazard identifier array; `hazardType` identifies this guidance event (`equipment`, `fire`, `gas`, `combined`, `position-unknown`, `sensor-unknown`). Priority is `critical|high|medium|low`. The server resolves combined hazards; RAG cannot choose priority, action, path or destination.

All nullable route fields are present explicitly. For actions without a route: `waypoints:[]`, `destinationId:null`, `routeVersion:null`, `stepId:null`. `POSITION_UNKNOWN`, `ROUTE_UNAVAILABLE`, `SENSOR_UNKNOWN`, `SHELTER_PER_SCENARIO`, `AWAIT_REOPEN_AUTHORIZATION` cannot carry movement paths. `FOLLOW_VALIDATED_ROUTE` requires at least two graph waypoints and non-null route/step/destination. A destination at the current node is represented by arrival, not an invented movement segment.

Guidance includes immutable run/incident/event/worker identity, guidance version, map/floor/version, route version, profile version, generation/expiry, evidence document/version/chunk and optional supplemental explanation. Freshness validation compares all of these relevant dependencies. UI, voice and vibration operate on one accepted primary guidance version. Supplemental text must not replace the primary message or restart primary speech.

Every envelope version is immutable. `updateKind:"primary"` has `primaryGuidanceVersion===guidanceVersion`; an explanation-only `updateKind:"supplement"` creates a newer envelope version referencing the earlier `primaryGuidanceVersion`. The server verifies all primary action/text/route/profile/map/hazard context and generated/expiry timestamps are unchanged before storing a supplement. Playback identity is `(runId,workerId,guidanceId,primaryGuidanceVersion)`; supplement receipt updates explanation/evidence without cancelling/replaying ongoing primary speech. Primary voice completion callbacks remain acceptable only while that exact primary lineage is active; latest supplement receipt is recorded separately. A new primary invalidates old callbacks. All envelope versions and supplement events append to history; firstGuidance remains the actual first delivered version.

Delivery and user actions remain separate: received, displayed, voice-started/completed/failed/unsupported, understood, help-requested, arrived. Incident support assignment/acceptance/completion are administrator/support events. None automatically implies another. Initial guidance stays immutable in `Incident.firstGuidance`; later messages append history and replace only current guidance.

## Map and coordinate contract

Map `SITE-CONSTRUCTION-01`, version `1.0.0`, floor `GROUND`, `synthetic:true`. Display label: “서산 HVO 현장 참고 / 상세 배치 재구성”. Logical XY bounds are `(0,0)`–`(140,50)` metres. Blender uses XY ground/Z height; standard glTF/Three coordinates are `[x,height,-y]`. GLBs stay one unit per metre, never scaled to the physical phone size.

The table is140cm×50cm, origin bottom-left, +X along the long edge, +Y along the short edge. Table centimetre values equal world metre values; table metre values multiply by100. Inverse operations divide by100. Roundtrip tolerance and physical accuracy testing remain the frozen QA protocol, not a manufacturer precision claim.

Map geometry contains exact work area x15–100/y12–38, storage x55–75/y17–29, lift destination x80–95/y17–29, obstacle x105–120/y18–30 at6m height, crane C=(30,25), and default jib+X. PATH-A/PATH-B follow y8/y42, width4m, x8–132; PATH-C links permitted connectors. Refuges are REFUGE-01=(125,8), REFUGE-02=(125,42). Worker starts are(65,25) and(90,40). No illustrative PATH-D is created.

Edges include `stairs`, `accessible`, `enabled`, and `initialEgress`. Four explicit start connectors support departure from an already occupied hazard; the route engine may allow only the initial segment to exit the containing hazard, with no re-entry or unrelated hazard intersection. This flag is never blanket permission for hazard-crossing paths. One documented synthetic stairs connector tests confirmed capability restrictions without changing the source's main4m corridors. Missing capabilities remain null and require conservative policy handling.

Map and engine risk polygons are distinct from GLB geometry/render interpolation. Model replacement atomically invalidates old risk geometry/routes/guidance before recomputation. SK1265 table-linked slew±15° is a demo rule; whole-site display retains original dimensions and identifies areas without physical phone observations.

## Tracking and device identity

Roles are chosen at runtime: EQUIPMENT→EQUIPMENT-A, WORKER_1→WORKER-A, WORKER_2→WORKER-B; CCTV has no worker identity. WORKER-C is virtual. No model whitelist establishes capability. Marker corner IDs0–3 correspond to `(0,0)`, `(1.4,0)`, `(1.4,0.5)`, `(0,0.5)` table metres; tracked markers10/11/12 identify equipment/A/B. Camera and UWB observations remain separate, with source, timestamp, sequence, uncertainty and calibration version. Native angular values convert to radians at the upload boundary. A missing angle stays null; distance-only data never creates XY. Antenna/marker/reference offsets and height are calibration inputs, not inferred truths.

## Knowledge normalization

RAG owns its canonical knowledge schema. Legacy003 `siteId` becomes one-element `siteIds`; source004 `common` remains a distinct document kind. Search includes `(request simulation mode OR common)` and always enforces the site filter. Legacy `status` maps to `approvalStatus` without collapsing `draft`, `approved_for_demo`, `approved`, `retired`. Synthetic documents start draft0.1.0 and become eligible only after recorded reviewer/time and `approved_for_demo`, in demo scope and their valid time interval. Demo approval never becomes actual `approved` automatically. Negative fixtures remain outside the normal index.

Only the eleven action codes in `ActionCodeSchema` are valid. The knowledge corpus cannot define new paths, locations, identifiers, numeric limits or control permissions. Actual document/version/chunk evidence and embedding/model/version/dimension data are retained. Generated additions are discarded on timeout, provider failure, invalid citation, meaning conflict or current-state mismatch; primary guidance remains available.
