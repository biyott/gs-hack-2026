# EQ-006 지정 회피 지점 도착 확인

## 1. 목적

현재 경로 엔진이 지정한 회피 지점의 도착 확인과 위험 해제 상태를 분리한다.

시뮬레이션 전용 합성 자료다. 실제 현장 사용 지침, 실제 승인·인증·법규 준수의 증거가 아니다. 위험·행동·경로·목적지는 서버 엔진이 결정하며 이 문서는 그 조건에 맞는 설명만 제공한다.

## 2. 적용 조건

equipment 실행에서 현재 유효 안내의 destinationId가 지정 회피 지점이며 엔진의 도착 판정 또는 작업자의 명시적 도착 응답을 기록하는 경우에 적용한다. 확인 출처를 구분한다.

검색 적용 시 siteIds, 요청 모드 또는 common, 위험 유형, 역할, 구역·물질·행동·프로필 조건, 유효기간을 모두 확인한다. 합성 문서는 독립 검토 기록과 approved_for_demo 상태가 확인된 데모 검색에서만 사용할 수 있다. draft, retired, 기한 전·만료 문서는 검색 근거에서 제외한다.

## 3. 적용 제외 조건

이전 안내 목적지, 다른 작업자의 도착, 수신·이해 확인만 있는 경우, 화재·가스 모드에는 적용하지 않는다.

## 4. 필요한 입력 필드

- `siteId`
- `simulationType`
- `runId`
- `workerId`
- `actionCode`
- `guidanceId`
- `guidanceVersion`
- `profileVersion`
- `expiresAt`
- `destinationId`
- `destinationLabel`
- `routeVersion`
- `arrivalStatus`
- `arrivalSource`
- `arrivedAt`

필수 입력이 없으면 추측으로 채우지 않고 미확인 또는 설정 필요로 남긴다. 이름·생년월일·의료 진단명은 본 검색 절차의 입력이 아니다.

## 5. 행동 코드와 설명

- `CONFIRM_ARRIVAL`: 현재 안내의 지정 목적지 도착 여부를 별도로 기록한다. 도착은 위험 해제나 통행 재개를 의미하지 않는다.

현재 엔진의 actionCode와 일치하는 설명만 사용한다. 본문은 하나의 절차 검색 단위로 유지하여 적용 조건·행동·예외를 함께 확인한다.

## 6. 개인화 적용

보조를 받은 경우에도 지원 수락과 실제 도착을 별도로 기록한다. 개인 제약에 맞는 목적지는 엔진이 결정한다.

언어는 preferredLocale을 사용하고 국적으로 추정하지 않는다. 나이·성별에서 이동 능력이나 이해 능력을 추정하지 않으며 미입력 프로필을 제약 없음으로 취급하지 않는다.

## 7. 예외 및 기본 안내

위치 불명이나 지도 버전 불일치로 엔진 도착을 확인할 수 없으면 확인 불가로 남긴다. 작업자 응답을 센서 검증 도착으로 바꾸지 않는다. 목적지 변경 시 이전 도착을 새 안내에 승계하지 않는다.

검색 근거 없음·충돌·모델 지연·실패·잘못된 인용·행동 불일치에는 보조 설명을 생략하고 검토된 기본 안내를 유지한다. 실제 경로·목적지·연결 관계·장비 제어·임계값을 생성하지 않는다.

## 8. 한국어 안내 예시

> 안내 {guidanceVersion}의 {destinationLabel}에 도착했다면 도착 확인을 눌러 주세요. 도착 확인은 위험 해제나 통행 재개 승인을 의미하지 않습니다.

## 9. 영어 안내 예시

> If you have arrived at {destinationLabel} for guidance {guidanceVersion}, select arrival confirmation. Arrival confirmation does not mean hazard clearance or authorization to reopen passage.

## 10. 확인할 상태

- 현재 목적지·경로 버전
- 도착 응답과 엔진 도착 판정의 출처
- 수신·이해·지원 수락과 별도의 도착
- 위험 해제와 별도 통행 재개

기기 수신 확인, 작업자의 이해 확인, 담당자의 지원 수락, 작업자 또는 엔진의 도착 확인은 각각 별도 상태이며 서로 자동 대체하지 않는다.
