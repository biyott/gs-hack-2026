# RAG integration contract 1.0.0

This simulation uses one Node application server and one server-owned SQLite connection. E5 inference runs inside Node. The separately launched llama.cpp executable is a configurable local model provider; it is not a second application backend and never reads the application database.

The authoritative engine publishes a reviewed primary action before starting RAG. `createRagService({db, embedding, llm})` exposes `initialize(repositoryRoot)` and asynchronous `enrichGuidance({guidance, context}, getCurrentGuidance)`. Initialization verifies the review ledger and warms/embeds the approved corpus. A returned supplement contains only explanation and evidence. The engine preserves its first guidance and publishes a new immutable supplement version referencing the same `primaryGuidanceVersion`, after checking current state again. Primary action/audio are not reissued by a supplement.

## Search and approval

Normal ingestion traverses only `knowledge/common`, `knowledge/equipment`, and `knowledge/fire-gas`. Initial drafts remain in `data/knowledge/drafts`; author revisions and independent review records are separate. `data/knowledge/reviews/approvals.json` joins every approved file hash to its reviewer, time, version and reviewable content hash. Changing reviewed body or metadata invalidates approval. Synthetic `approved_for_demo` documents are usable only in demo scope. A legacy singular site/status is normalized without dropping original metadata; `common` expands permitted modes but never expands sites.

Eligibility checks status, dates, site, mode, hazard, role, area, material, engine action, explicit policy and confirmed functional profile. SQLite FTS5 and the actual multilingual embedding model operate after eligibility filtering. The store persists vectors, exact model revision and dimensions. Cosine similarity is calculated in memory. Individual keyword/vector/filter/fused results are recorded; scores are ranking signals, never safety probabilities. Documents retain all twelve procedural sections in a single bounded chunk so conditions/actions/exceptions stay together.

Operative conditions also require private authoritative context. FG-002 needs a proved prior route invalidated by fire, a current validated replacement route and an explicit movement policy. EQ-002 needs a proved equipment direction change followed by new primary guidance. The backend derives these facts from the exact primary transition in durable same-run worker history; route-version thresholds and query text do not establish them. Missing facts exclude those procedures before ranking and model selection. Retrieval traces record supplied applicability facts. Controlled test fixtures may supply explicit facts to test filtering, but those fixtures do not prove production derivation. Original corpus/review files and earlier retrieval fixtures remain preserved.

## Model output boundary

Default local generation is **reviewed extractive selection**. The actual LLM chooses one index among retrieved bilingual reviewed explanation candidates. The application resolves that index to its exact reviewed text and citation. This avoids inventing routes, destinations, identifiers, numbers, units, or urgent instructions; it is not represented as free-form model-authored safety advice. Actual provider call IDs and raw selection response SHA-256 are recorded. Other providers implementing `LanguageModelProvider` can return a full candidate supplement, which passes the same validator.

Output must match the engine action and chosen locale, cite an actual retrieved document/version/chunk, and exactly match an independently reviewed explanation for that language. Prompt-like source instructions are rejected before indexing and again at validation. Source contradictions return `conflict`, never an arbitrary winner. No match, malformed output, incorrect citation, reversed meaning, added identifiers/placeholders/numbers, provider failure and delay retain the original template.

A supplement's total search/generation deadline is 5000ms by default. Elapsed time at or after the deadline is rejected. Cancellation is signalled and late results cannot apply or change the recorded outcome. This is a bounded implementation policy, not a promise that all hardware or cold models finish in that time. Initialization is outside the urgent path; cold model loading must finish before normal-model demonstrations. Freshness includes run, target, incident, event, guidance, action, route, profile, map, locale, hazards, destination, waypoints and expiry. Changes during generation invalidate its result.

## Providers and evidence

The default model preparation, pins, SHA-256 and launch commands are in [runtime README](../data/knowledge/runtime/README.md). No paid API or private credentials are required for the local path. Provider adapters are replaceable; model ID/revision/dimension/base URL are explicit configuration. Only the requested action, locale and reviewed evidence candidates go to the LLM. Names, demographics, diagnoses, birth dates and raw personal profiles are excluded.

SQLite stores `knowledge_documents`, `knowledge_chunks`, `knowledge_embeddings`, `knowledge_fts`, `rag_runs` and `guidance_evidence`. `rag_runs` distinguishes provider `mode: actual` versus `mock`. Unit and fault tests deliberately use mock providers and do not establish actual model execution. Actual probe reports record model calls, vectors, query results and validated matched supplements separately. Maker self-checks are not the independent AC06–08 QA verdict.
