# Guidance catalog and lifecycle

Catalog version: `1.0.0`. Requirement baseline: `GS-SAFETY-SIM-001` version `1.0`, run `GS-SAFETY-SIM-001-20260921T084101Z`, source documents 003, 005 and 006.

The eleven action codes in the shared contract have short Korean and English messages. An independent read-only bilingual semantic review was performed by `/root/backend_lead/guidance/catalog_review` on 2026-09-21; review and implementation were recorded by `/root/backend_lead/guidance` at `2026-09-21T09:00:14Z`. This is an internal simulation template review, not site approval or the QA Lead's acceptance verdict.

The review checked equivalent movement, waiting, assistance and confirmation meanings, preservation of engine destination identifiers, and absence of invented physical routes or gas rules. Its two conditional findings were retained: route updates keep `FOLLOW_VALIDATED_ROUTE` and receive a new version; `SHELTER_PER_SCENARIO` applies only after authoritative scenario policy identifies indoor waiting as the current action. Movement to shelter must first use a validated route instruction.

`createGuidance(decision, context, previous)` (also exported as `buildGuidance`) is pure and does not call RAG, a model, a clock or persistence. The caller supplies the authoritative engine decision, shared map identifiers, current profile, route version/step and issuance timestamps. The caller must have applied the shelter policy and route constraints before this formatting boundary. Only `FOLLOW_VALIDATED_ROUTE` carries routing metadata; all other actions clear waypoints, destination, route version and step.

The context's `messageArgs` carries semantic input versions such as `geometryVersion` or `policyVersion`; changing them reissues even a nonroute action. `forceReissue: true` records an explicit administrator follow-up. Unchanged valid semantics return the previous record, preserving timestamps and avoiding duplicate notifications from position snapshots. Once the previous record expires, a new version renews validity. The caller remains responsible for rejecting stale commands and issuing valid future expiry timestamps.

The guidance ID is stable per run, incident and worker. A changed action, hazard set/type/priority, route/version/step, map, profile, language or semantic argument increases the guidance version. A new run, incident or worker starts a new lineage at version 1. Every new primary envelope sets `updateKind: primary` and `primaryGuidanceVersion` to its new version. RAG supplement metadata and explanation changes are excluded from basic-action deduplication, preserving the latest unchanged supplemental envelope; a subsequent primary advances past its version. This module never creates or validates supplements.

Korean and English language tags resolve to `ko` and `en`; other or missing preferences use predetermined English fallback, retain the exact requested locale and set `fallbackLocaleUsed`. The actual primary text has a common `⚠` sign for fallback. Every record contains the Korean manager explanation and the profile conditions as they existed at issuance. No nationality, age or gender inference occurs.

New records and `preserveFirstGuidance(first, current)` snapshots are detached and recursively frozen. Unchanged records restored from persistence become detached frozen copies without a new version or event; already-frozen records preserve object identity. The helper preserves the first guidance contents when later versions arrive. Persistence should store that initial snapshot once and append later versions, keeping delivery and user-response statuses separate.

Self-checks: `npm test -- src/server/guidance` after shared dependencies are installed. Unit tests cover the eleven bilingual actions, supported and fallback locales, route clearance, stable IDs and monotonic versions, expiry renewal, explicit follow-up, geometry invalidation, source-input detachment, immutable first guidance and primary/supplement version tracking.
